# Historical measurement evidence

This compact package preserves the original records behind the paper's historical performance claims. It supports analysis after relocation with Python 3.10 or later and the standard library. It contains no solver binaries or solver source trees. Analysis does not execute a design solver, a historical launch script, or a command found in a log.

From the standalone code repository root:

```bash
python3 evaluation/historical/analyze.py --check
python3 evaluation/historical/test_historical.py
```

To regenerate `summary.json`, `claims.json`, `claims.tex`, `dystrophin-table.tex` and `historical-results.tex`:

```bash
python3 evaluation/historical/analyze.py
```

An independent destination is supported with `--output /tmp/historical-regenerated`. The analyzer verifies compressed and decompressed source hashes, restores records in a temporary directory, runs the three preserved strict analyzers, checks the July 23 pair, and generates every included numerical claim from the results. Generated files contain no temporary execution paths. `--check` compares regenerated bytes without rewriting them. `SHA256SUMS` verifies the entire packaged directory.

## Separate protocols

| Dataset | Records included | Interpretation |
|---|---|---|
| July 14 multiloop ablation | 48 CSV records, 24 adjacent dense/sparse pairs: two proteins, two lambda values, two thread counts, three repetitions | Historical same-source **complete multiloop replacement**, including pair-type collapse and recurrence orientation. It does not isolate pruning. The CSV includes original harness stdout/stderr, GNU-time transcripts, scheduling, loads, commands and dependency hashes. |
| July 13 dystrophin | Five sparse and five local dense thread-ladder runs; five separately launched sparse j16 repeats; twelve j4/j8 node comparisons | These remain separate groups. Each ladder point has one measurement. The five repeats were selected across NUMA nodes and are not pooled with the ladder. All original outputs, time files and launch records are retained. |
| July 23 dystrophin | One local dense j16 run followed by one sparse j16 run, bound to node 1 | This separate sequential pair is not a replicate of July 13. Its sparse executable hash differs. Chronology, commands, zero exits, empty stderr, common reported MFE and output lengths are checked. |
| July 14 packed layout | Four cost-only measurements in B,D,D,B order and one subsequent full packed CLI run | Two runs per layout. This compares the square layout against the position-major packed layout as a combined implementation change. The full CLI run is excluded from the cost-only medians. |

For the ablation, speedups are medians of the **within-pair dense/sparse ratios**, separately for harness solve time and external wall time. The paper's approximately 1.408–1.607 range is the solve-time range over four Q6UXY8 conditions. Original deterministic paired-bootstrap intervals (10,000 draws, seed 20260714) are regenerated by the preserved analyzer. With three pairs per condition, those intervals describe repeat resampling only.

The packed-layout percentages are **ratios of layout medians**, with solve time taken from the cost harness and peak RSS from GNU time. They are not a pooled historical speedup. RSS conversion is exactly KiB / 1,048,576 = GiB. The original July 13 sparse j16 record is 21,105,896 KiB, rounding to 20.13 GiB; the regenerated table corrects a previous 20.10 transcription. Printed RNA free energies and CAI values are retained as reported. At lambda zero, different CAI values are compatible with an equal objective.

## Original source boundaries

All experiments used the historical shared dual-socket AMD EPYC 7313 server. The raw records preserve its hardware snapshots, affinity, load, compiler and timing metadata where originally recorded. These observations do not inherit the current release's source identity or the current workstation timing protocol.

The July 13/23 dense comparator is the **locally parallelized dense LinearDesign fork**, not stock upstream LinearDesign. `summary.json` records the historical binary identifiers and the dense source commit stated by the original dataset. The ablation's final square-build note supersedes the older packed-default build note, which is retained and clearly labelled. Packed-layout frozen manifests record its original source and binary identifiers.

These are retained identity claims, not a fresh authentication or rebuild of omitted binaries. The July 13 dataset does not supply a complete frozen sparse-source tree, and the July 23 sparse binary hash alone does not establish source identity. Current solver tests cannot retroactively establish which changes were present in these historical builds.

Original recorded independent validation reports are included where available, but this stdlib analysis does not rerun thermodynamic evaluation, translation or CAI recomputation. Its checks cover records, reported objectives, scheduling, completeness, arithmetic and provenance consistency. The original analyzers describe their individual verification boundaries in their source and summaries.

## Files and provenance

- `inputs.json`: original repository paths, original SHA-256/byte counts, and compressed SHA-256/byte counts for every retained record; hashes for the three unchanged analysis sources.
- `raw/`: deterministic, lossless gzip copies of the original records. Original `SHA256SUMS` files are themselves retained as records. They can reference binaries or unrelated historical dependencies deliberately omitted here; the new manifest enumerates the exact packaged subset.
- `source/`: unchanged original stdlib analyzers for ablation, July 13 dystrophin and packed layout. The top-level wrapper supplies relocated inputs instead of their historical defaults.
- `summary.json`: complete validated numeric results, original build identities and explicit verification boundaries.
- `claims.json`, `claims.tex`, `dystrophin-table.tex`, `historical-results.tex`: generated numbers and LaTeX inputs. The last file combines the macros with `\HistDystrophinTableRows` for direct manuscript use.
- `test_historical.py`: corrupted-input, duplicate-input, missing-repeat and failed-run rejection checks.
- `freeze_inputs.py`: packaging recipe. Its optional package-reconstruction command is `python3 evaluation/historical/freeze_inputs.py --original-repo /path/to/original/workspace`; the original workspace is needed only to reconstruct the package, not to analyze it. Historical `.sh` files are compressed protocol documentation, not runnable release instructions.

Keep these recorded findings separate from new scalar pruning controls and workstation timing results. Neither the historical kernel ratio nor the large-instance whole-process ratio should be multiplied into an attribution of other implementation gains.
